# Security policy

## Reporting

Do not open a public issue for a suspected vulnerability. Use GitHub Private Vulnerability Reporting for this repository. If that channel is unavailable, contact the repository owner privately through the verified GitHub profile before disclosing details.

Include affected version/SHA, impact, reproduction, prerequisites, and any suggested mitigation. Do not access data or systems you do not own, disrupt live services, or publish secrets.

## Response targets

- Acknowledge within 3 business days.
- Initial severity assessment within 7 business days.
- Coordinate remediation and disclosure based on impact and release availability.

## Supported versions

Before v1.0, only the latest released version receives security updates. This policy will be revised before GA.

## Boundaries

Security-sensitive work requires threat-model evidence and independent exact-head review. Critical/high findings block release and merge.
